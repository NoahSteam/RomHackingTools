# 03 — VDP1

## VDP1-01 — High — shared 16-bit reader has a wraparound OOB path

Same root cause as ABI-01 in `ByteOrder.h`. Fix centrally.

## VDP1-02 — Medium — sprite priority is resolved per command, not per pixel

`Context::ResolveSpritePriorities()` assigns one priority to each sprite. Multiple Saturn SPCTL modes encode priority-number bits in pixel/color data, so one sprite can contain pixels at different priorities.

The current code chooses the highest reachable priority for the entire sprite, which can put pixels in front of VDP2 layers that should cover them.

**Fix:** resolve priority per texel and carry it into the pixel mixer.

## VDP1-03 — Low — 3D view omits line/polyline primitives

`Render3D` and `HitTest3D` skip those primitives. Either render them or document that the exploded view is not a complete representation of the VDP1 list.
