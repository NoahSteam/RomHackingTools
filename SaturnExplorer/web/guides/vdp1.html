VDP1 — the Saturn's drawing engine

The chip that paints the moving stuff: characters, ships, effects, and fake-3D polygons. A plain-English tour of how it draws, and the tools that let you select, inspect, and extract every piece. No hardware knowledge assumed.

The one thing to remember

Everything VDP1 draws is a four-cornered quad

Unlike an old 2D console, VDP1 doesn't think in fixed sprites at an X/Y spot. It thinks in quads — shapes with four independently placed corners. The three sprite types are really just how warped those corners are.

Normal sprite

An upright rectangle. The plain case.

Scaled sprite

The same quad, stretched bigger or smaller.

Distorted sprite

Corners dragged anywhere — how the Saturn fakes 3D.

Under the hood all textured sprites are distorted sprites; the upright and scaled ones are just the easy special cases. VDP1 also draws untextured polygons, polylines, and lines.

How it works

A to-do list, a texture, and a frame buffer

VDP1 works through a list of drawing commands each frame and paints the results into an off-screen image, which it then hands to VDP2 for final layering.

The command table

VDP1 is driven by a command table in its memory — a linked list of drawing commands it walks in order (they can jump, call, and return like little subroutines) until it hits an end marker. Each command is 15 words (32 bytes) describing one thing to draw: its type, texture address, four corner coordinates, color mode, and options. You'll see these field names in the tool — CMDCTRL, LINK, PMOD, COLR, SRCA, SIZE, XA…YD, GRDA.

Textures and color modes

A textured sprite reads its picture from VDP1 memory in one of several color modes, trading color count against memory:

ModeColorsHow pixels are stored
16 (bank)164 bits/pixel — index into a 16-color slice of the palette
16 (LUT)164 bits/pixel — a small lookup table in VDP1 memory picks the colors
64 / 128 / 256 (bank)64–2568 bits/pixel — index into a larger palette slice
RGB555~32,00016 bits/pixel — the color is written directly, no palette

"Bank" and "LUT" modes are palettized: pixels are just index numbers that look up real colors. RGB555 is direct color — each pixel already is a color, at twice the memory. Universal rule: palette index 0 = transparent (unless a command disables that).

The palette lives in VDP2. Palettized textures don't carry their own colors — the real RGB values sit in Color RAM (CRAM), a palette shared with VDP2. A texture pixel says "color #37"; CRAM says what #37 looks like. So understanding or recoloring a sprite usually means looking at both the texture and the palette.

Gouraud, draw modes, flips

Each command can add effects: Gouraud shading blends brightness smoothly across the quad from its four corners (so a flat texture looks lit); draw modes control how it combines with what's already there — Normal, Mesh (a stipple that fakes transparency), Shadow, Half Luminance, and Half Transparent; and flip mirrors the texture.

The double frame buffer

VDP1 has two frame buffers (512×256 pixels) and swaps them: it draws into one while the other is on screen, then flips — so you never see a half-drawn frame.

The toolkit

What each VDP1 tool does

The tool contains a software VDP1 that rebuilds the frame from the individual commands — exactly like the real chip — so every sprite stays a separate, selectable object rather than a flat image.

List · commands

VDP1 Command List

A table of every command to be drawn — #, type (Normal / Scaled / Distorted / Polygon / Line / clip / coordinate), size, position, color mode, and texture address. Click to select; Shift-click for several; double-click to jump to its bytes.

Use it to browse everything on screen and find a specific object.
Inspect · one object

Selected Object

The full decode of one command: table / link / texture / palette addresses, size, position, color mode, draw mode, transparency, Gouraud, color-calc, flip, and the raw CMDCTRL / CMDPMOD words.

Use it to read exactly how one sprite is configured.
Decode · picture

Texture Viewer

Decodes the selected sprite's texture over a checkerboard (transparent pixels read clearly), with its dimensions, color mode, and address. Export to a BMP that keeps the game's palette; right-click to break when it's written, or jump to its bytes.

Use it to see and extract a sprite's artwork.
Decode · colors

Palette Viewer

Shows the palette a palettized sprite draws from — its shared CRAM bank, or a LUT-mode lookup table — as a grid of swatches with index and RGB on hover. (Direct-color sprites have no palette, and it says so.)

Use it to read and note the colors behind a sprite.
Map · memory

VRAM Map (VDP1)

A color-coded map of all 512 KB — Command Table, Texture, CLUT, Gouraud Table, Unused, Other — with a legend and a "% used" readout. Hover a block for its address, size, and owning command; click to select it.

Use it to see how a game budgets its graphics memory.
Explore · in space

3D View

Renders the frame's quads as objects you can orbit and zoom, separated along depth so you can see the layering. Click to select, Shift-click to add — the tool ray-tests your click against the real geometry. Selection is shared with every panel.

Use it to untangle overlapping sprites and pick the right one.
Result · pixels

VDP Output & Framebuffer

VDP Output shows the reconstructed scene with wireframe / bounding-box / object-number toggles. The Framebuffer panel shows the raw 512×256 buffer with Resolved, Raw RGB555, and Priority heatmap modes.

Use it to compare the rebuilt scene with what VDP1 actually drew.
Registers · knobs

Registers (VDP1 tab)

Lists VDP1's registers by name — TVMR, FBCR, PTMR, EWDR, EWLR, EWRR, ENDR, EDSR, LOPR, COPR, MODR. Most drawing state lives in the command table, so the command panels above are usually where the action is.

Use it to check the chip's mode and status registers.

Start to finish

The drawing pipeline

The journey every VDP1 frame takes — each stage maps to a panel that shows it.

Command table

The game builds its to-do list in VDP1 memory. → VRAM Map, Command List

Walk the list

VDP1 follows the linked commands — jump, call, return — one by one. → Command List

Build quads

Each command becomes a four-corner quad with a texture. → Selected Object, VDP1 Table

Rasterize

The texture is stretched over the quad; palette colors are looked up; Gouraud and draw modes apply. → Texture & Palette Viewer

Frame buffer

The result is painted into one of the two 512×256 buffers. → VDP1 Framebuffer

Hand off to VDP2

The finished sprite layer goes to VDP2 for final compositing. → see the VDP2 guide

Worked example — "how is this sprite drawn?"  Click it in the 3D View → read Selected Object for its mode and corners → open the Texture Viewer and Export it → check the Palette Viewer for its colors → use the VRAM Map to see exactly where its texture and command live in memory.

Before you get confused

A few things to watch out for

🧩

VDP1 has no "screenshot" to read back

The real chip doesn't keep an addressable finished image — so the tool rebuilds the frame from the commands. That's the whole point: it's why every sprite is a separate, selectable object instead of a flat picture.

🖥️

The frame buffer needs a live software renderer

The raw 512×256 buffer view is only populated when connected to a live emulator using its software renderer. Savestates and hardware-accelerated renderers won't have it — the panel will say so.

🎨

Sprite colors depend on VDP2

A palettized texture is just index numbers; its real colors come from VDP2's Color RAM, and the final look also depends on VDP2 sprite settings. If a sprite's colors look wrong, check the palette — not just the texture. (Memory is big-endian but the frame buffer is host-order, which is why the Framebuffer panel has a byte-swap toggle.)

The Saturn's drawing engine; draws sprites and polygons into a frame buffer.
VDP2
The companion chip that draws backgrounds and composites the final picture.

On the Saturn, a textured quad — not a fixed-size 2D tile.
Quad

Distorted sprite

Command table
The linked list of drawing commands VDP1 works through each frame.
Texture
The picture stretched across a sprite, stored in VDP1 memory.
Color mode
How a texture stores pixels: 16/64/128/256-color palettized, or direct RGB555.
CRAM
Color RAM — the shared color table palettized pixels look up.
CLUT
A small color lookup table in VDP1 memory used by "16 (LUT)" textures.
Gouraud
Smooth brightness blended across a quad from its four corners.
Draw mode
How a sprite blends: Normal, Mesh, Shadow, Half Luminance, Half Transparent.
Frame buffer

RGB555
A direct-color format: 5 bits each for red, green, blue.
