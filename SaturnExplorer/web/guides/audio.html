Saturn Explorer · Field Guide

How the Sega Saturn makes sound — and how to trace it

A plain-English tour of the Saturn's audio hardware and the tools that let you see, hear, extract, and follow any sound all the way back to its file on the disc. No prior hardware knowledge assumed.

32-voice SCSP 512 KB sound RAM 68000 sound CPU PCM samples FAD → file

The one thing to remember

Two completely separate paths to your ears

Knowing which path a game is using tells you which tool to reach for. Almost everything in this guide is about the first one — it's the rich, inspectable path.

Path 01 · inspectable

Sampled & synthesized

Sound effects, voices, and most music are short recordings ("samples") played back by a dedicated sound chip that bends their pitch, volume, and stereo position on the fly.

game data→ sound RAM→ SCSP chip→ speakers

You can inspect all of it — the samples live in memory you can read.

Path 02 · hardware-mixed

CD audio (CD-DA)

Some games store full music tracks on the disc as ordinary Red Book audio — like a normal music CD. The console just spins the disc and pipes it straight to the speakers.

audio track→ CD drive→ speakers

Bypasses the chip and memory entirely. Nothing to inspect in RAM.

The hardware, path 01

The cast of characters

Picture the Saturn's sound system as a small self-contained studio bolted onto the main console.

PartWhat it does
SCSPthe sound chip The synthesizer. Plays up to 32 sounds at once, each with its own pitch, volume, and pan. (Saturn Custom Sound Processor.)
68000the sound CPU A small second processor running the sound program — deciding which notes to trigger, when, and how loud. The main game hands it commands; it handles the music.
Sound RAMthe sound memory 512 KB holding both the program the 68000 runs and the raw samples the SCSP plays. If you can read it, you can grab the audio.
SH-2 ×2the game The two main processors running the actual game. They tell the sound system what to play.

Voices (a.k.a. "slots")

The SCSP has 32 playback channels called voices. At any instant a voice is silent or playing one sample. A busy battle might have a dozen going at once — drums on one, a melody on another, a sword clang on a third. Each active voice carries: which sample and how far into it, the format, the pitch (play it faster and the note is higher), a volume envelope (the fade-in / hold / fade-out shape that makes a note swell and die instead of clicking on and off), pan, and loop points.

Sample formats

Samples are stored as plain PCM — uncompressed audio — in one of two sizes: 16-bit (full quality) or 8-bit (half the size, a touch noisier). That's the whole list. The Dreamcast's 4-bit ADPCM compression is not a Saturn feature.

Streaming — the case you'll trace most

512 KB isn't much. Long music or lengthy voice lines won't fit, so games stream them: they keep only a small chunk in sound RAM and the CPU continuously refills it from the disc as it plays — like pouring water through a funnel that never fills up. That refilled region is a ring buffer (playback chases the writer around a circular patch of memory). This is the case where "where is this audio coming from?" has a real answer on the disc.

Finding a spot on the disc. Saturn CD addresses are called FAD (Frame Address) — a sector number. One quirk: FAD = LBA + 150, because a CD has a 2-second lead-in gap before the data. Once you know the FAD the drive is reading, you can look up which file contains that sector — the final link between "I hear this" and "it's this file."

The toolkit

What each audio tool does

Each feature inspects a different stage of the pipeline. Together they cover the whole journey from "a voice is sounding" to "here's the file on the disc."

Live · voices

Sound (SCSP) panel

One row per voice, all 32. See format, pitch (Hz), envelope stage & level, pan, loops, and how far playback has progressed. Silent voices grey out, so you can tell at a glance how many — and which — sounds are live. Each row has Play (preview in-app) and Export (save as .wav).

Use it to identify the voices in a scene, hear each in isolation, and pull out individual effects, instruments, or voice clips.
Memory · raw bytes

Sound RAM tab

A hex view of the full 512 KB — both the 68000's program and the sample data. A voice's start address links straight here, so you can jump to the exact bytes it's playing. You can also edit it live, which is how a music- or effect-swap experiment begins.

Use it to see the actual sample bytes, confirm what a voice points at, or poke sound memory to test a change.
Trace · code

Access Log

Point it at an address and it records which instructions read or wrote it, plus the call stack that led there. For streamed audio, this finds the routine refilling the ring buffer — the code actually feeding the sound.

Use it to answer "what part of the game is writing this audio into memory?" and walk back to the code that decided to play it.
Disc · files + live

Disc Explorer

Browses the disc's filesystem — every file with its size and byte offset in the image, sorted biggest-first (streamed audio is usually one of the largest). Its live drive readout shows what the CD is doing this frame and names the file the current FAD falls in.

Use it to turn "audio is streaming" into a filename and offset, in real time.
Debug · sound engine

68000 sound-CPU debugging

Disassemble and step through the little 68000 that runs the music engine — the logic that sequences the audio, not just the samples it uses.

Use it to understand how a game drives its music.

Start to finish

Hear a sound → find it → extract it

The end-to-end workflow the audio tools are built around. Say a battle theme is playing and you want to find and extract it.

See what's sounding

Open the Sound (SCSP) panel and watch which voices light up. Play to confirm you've found the right ones; Export to save any voice as a .wav.

Is it streamed?

If the music is long, it's almost certainly streamed from disc. Note the voice's start address and jump into the Sound RAM tab to see the buffer it plays from.

Find the feeder (optional)

Point the Access Log at that buffer to catch the code refilling it — handy if you want to understand or modify the streaming.

Find it on the disc

Open the Disc Explorer. With the game running, the live drive readout shows the FAD being read and names the file — e.g. /SOUND/BATTLE01.PCM. That's your source file.

Extract it

Grab the file's image offset from the Disc Explorer to pull the raw stream out of the disc image — or just use the Sound panel's Export for individual voices.

The same chain works for sound effects and voice clips — they're just shorter and usually already fully resident in sound RAM, so you can skip the streaming steps.

Before you get confused

A few things to watch out for

💿

CD-DA tracks are invisible to the sound tools

If a game plays music as a plain CD audio track, it bypasses sound RAM — so the Sound panel won't show it and there are no samples to export. The live readout still shows "playing (CD-DA)" and a FAD, but that FAD points into an audio track, so it reads (no file; audio track or gap). This is expected — the tool is correctly saying "this audio doesn't live in the filesystem." To extract CD-DA, rip the audio track itself, like ripping a music CD.

🌊

Streamed vs. resident

Short sounds sit entirely in sound RAM and are easy to grab. Long sounds are streamed and only partly present at any moment — which is exactly why the disc-side tools (live FAD + Disc Explorer) exist.

🔌

Live features need the emulator hookup

The real-time panels (live voices, live drive readout) work when Saturn Explorer is connected to a running emulator built with its data taps. If you've just updated the tool, re-run update.bat once so the patcher installs the latest hooks — then the live readouts light up.

Reference

Glossary

SCSP
The Saturn's sound chip; plays up to 32 samples at once with pitch, volume, and pan.
Voice / slot
One of the SCSP's 32 simultaneous playback channels.
Sound RAM
512 KB of memory holding the sound program and the audio samples.
68000
The small dedicated processor that runs the music engine.
PCM
Uncompressed audio; the Saturn uses 8-bit or 16-bit PCM.
Envelope
How a sound's volume changes over time — fade in, hold, fade out.
Ring buffer
Playing audio too big for memory by continuously refilling a small circular buffer from disc.
CD-DA
Plain CD audio tracks; mixed in hardware, bypasses the SCSP.
FAD
Frame Address — a CD sector address. FAD = LBA + 150.
LBA
Logical Block Address — the plain sector number from the start of the data.
ISO 9660
The standard filesystem layout on a CD, used to list the disc's files.
SH-2
The Saturn's two main game processors.
