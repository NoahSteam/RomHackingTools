The one thing to remember

VDP2 is a stack of layers, merged by priority

Where VDP1 draws things, VDP2 arranges them. Every frame it builds several scrolling backgrounds, takes VDP1's sprite layer, and merges them all — deciding, per pixel, which shows in front and whether layers blend. Picture a stack of transparent sheets, top wins:

How it works

Backgrounds, a shared palette, and color math

VDP2 shows up to five backgrounds — four flat scrolling ones and one that can rotate — then colors, prioritizes, and blends them.

LayerWhat it's for
NBG0Scroll AA normal scrolling background
NBG1Scroll BA normal scrolling background
NBG2Scroll CA normal scrolling background
NBG3Scroll DA normal scrolling background
RBG0RotationRotates, scales, and tilts — Mode-7-style floors and ceilings

Not every game uses all five — richer layers cost more memory bandwidth, so games trade layers against color and detail.

How a background is built: plane → page → pattern → cell

A background isn't one giant image — that's too much memory. It's assembled from small reusable tiles in a four-level hierarchy: a cell is an 8×8-pixel tile; a pattern ("character") is cells plus which palette and flip to use; a page is a grid of patterns; a plane is a grid of pages — the full scrollable map. Change one tile and it updates everywhere it's used. (A background can also be a flat bitmap when a game prefers that.)

Scrolling and line effects

Backgrounds move by changing their scroll position, with sub-pixel fractional scroll and zoom on the main layers. Line scroll gives each scanline its own offset — how games make water ripple, floors recede, and heat shimmer.

The palette is shared with VDP1. VDP2 owns Color RAM (CRAM) — up to 2048 colors. Both VDP2's tile backgrounds and VDP1's palettized sprites look their colors up here, so CRAM is the one place the whole console's palette lives. Modes: RGB555 (1024 or 2048 colors) or higher-precision RGB888 (1024).

Priority: who's in front

Every layer carries a priority number; when layers overlap, higher priority wins that pixel. Priority 0 means "not displayed" — it's how a layer is switched off. On a tie, VDP1's sprite sits in front of a same-priority background, so characters stay on top of scenery they share a priority with.

Color math (translucency)

VDP2 can make a layer semi-transparent and blend it with the layer right beneath — color calculation. A ratio blend mixes the two by a set percentage (glass, water, ghosts); an additive blend adds the colors (glows, light). It only ever combines the top pixel with the one immediately below.

Extra tricks

Back screen — the backdrop, one color or per-scanline (sky gradients). Color offset — nudge a layer's R/G/B for fades and tints. Mosaic — chunk a layer into big blocks (the pixelated-censor effect). Windows — mask a layer to a region so an effect only shows inside or outside a shape. Rotation (RBG0) — spin, scale, and tilt via rotation-parameter and coefficient tables.

The toolkit

What each VDP2 tool does

The tool contains a software VDP2 compositor that rebuilds the backgrounds and merges them with VDP1's sprites — so you can toggle layers, inspect the palette, and read the register state driving it all.

Summary · layers

VDP2 Table

One row per background (NBG0–3): whether it's On, its color depth (16 / 256 / 2048 / 32K), its priority, and its scroll (X, Y). The fastest way to see which layers are active and how they stack.

Use it to read the layer lineup at a glance.
Isolate · sheets

Layer toggles & VDP Output

The output view composites the whole scene; the Layers menu switches NBG0–3, RBG0, and the sprite layer on and off independently — plus color-calc and windows.

Use it to find which layer an element belongs to — turn layers off one by one.
Palette · all colors

Color RAM

A grid of every color in Color RAM (up to 2048 swatches) with the current mode (RGB555 / RGB888). Hover for index, raw value, and RGB. Because CRAM is shared, this is the palette behind both backgrounds and sprites.

Use it to inspect or plan a recolor of the whole palette.
Palette · one object

Palette Viewer

Focused on the selected VDP1 sprite, it shows the exact CRAM bank (or LUT) that object draws from — the bridge between "this sprite" and "these colors" in the shared palette.

Use it to connect a specific object to its colors.
Registers · control

Registers (VDP2 tab)

A curated list by name and value — resolution (TVMD), memory mode (RAMCTL), which layers are on (BGON), tile formats, priorities (PRINA/PRINB/PRIR), scroll, color-calc (CCCTL), windows, sprite control (SPCTL).

Use it to see exactly how a frame is configured — ground truth.
Quick diagnosis

"Where did my background go?"

Nine times out of ten a missing layer is a priority of 0 or its enable bit off in BGON — both visible in the VDP2 Table and the Registers panel. Check there before assuming anything's broken.

Start to finish

How a frame is composited

The layers line up with the tools stage by stage.

Back screen

The frame is seeded with a backdrop color. → Registers, VDP Output

Build backgrounds

NBG0–3 and RBG0 are assembled from tile maps (or bitmaps) and scrolled. → VDP2 Table, Layer toggles

Look up colors

Palette indices resolve to real colors in Color RAM. → Color RAM, Palette Viewer

Apply priority

Per pixel, the highest-priority layer wins. → VDP2 Table (priority)

Merge sprites

VDP1's sprite layer is mixed in, winning priority ties. → see the VDP1 guide

Color math

Semi-transparent top layers blend with the one below. → Color Calc toggle

Worked example — "which layer is this, and how is it colored?"  In VDP Output, toggle backgrounds off one by one until the element vanishes — now you know the layer → check its VDP2 Table row (depth, priority, scroll) → open Color RAM for its palette → read the Registers if it's missing (usually priority 0 or a BGON bit).

Before you get confused

A few things to watch out for

🫥

Priority 0 = invisible

If a background you expect is missing, the usual cause is a priority of 0 or its enable bit being off in BGON — check the VDP2 Table and Registers before assuming anything's broken.

🎨

The palette is shared, and backgrounds are tiles

Editing a Color RAM entry changes it for every background and sprite using that index — great for recoloring, but watch for side effects. Likewise, changing one cell updates it everywhere that tile appears on the map.

🧪

Some advanced effects are approximated

The compositor models the common, high-impact features — scrolling, zoom, line scroll, rotation, color math, color offset, horizontal mosaic, windows, and the back screen. A few less-common ones aren't yet modeled: VDP2 shadow/highlight, the line-color screen, vertical cell-scroll, vertical mosaic, and true per-pixel sprite priority. A scene leaning heavily on those may look slightly different from real hardware (some UI toggles exist ahead of the feature).

Glossary

VDP2
The Saturn's background and compositing chip; draws scenery and stacks all layers.
VDP1
The companion chip that draws sprites and polygons into a frame buffer.
NBG0–NBG3
The four normal (flat) scrolling backgrounds; also called Scroll A–D.
RBG0
The rotation background; can spin, scale, and tilt.
Cell
An 8×8-pixel tile, the smallest piece of a tiled background.
Pattern
One or more cells plus palette and flip info (a "character").
Page / plane
Grids that arrange patterns into a full scrollable map.
Bitmap background
A background stored as one flat image instead of tiles.
Color RAM (CRAM)
The shared color palette (up to 2048 colors) used by VDP2 and VDP1.
Priority
The number that decides which layer shows in front; 0 means hidden.
Color calculation
VDP2's translucency: blending the top layer with the one below.
Back screen
The backdrop color behind everything, at the bottom of the stack.
Line scroll
Giving each scanline its own scroll offset, for ripple and recede effects.
Mosaic
Chunking a layer into big blocks — the pixelated-censor effect.
Window
Masking a layer to a region so an effect shows only inside or outside a shape.
Color offset
Shifting a layer's red/green/blue for fades and tints.
