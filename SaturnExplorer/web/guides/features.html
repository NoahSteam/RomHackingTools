Saturn Explorer

Everything Saturn Explorer can do

A visual reverse-engineering and debugging tool for Sega Saturn games. Point it at a savestate, a memory dump, or a running emulator: it rebuilds — in software — what the console is drawing from raw VRAM, and lets you step through the SH-2 code behind it. This page is a plain-English tour of every panel, tool, and workflow.

What it is

A Saturn graphics reconstructor + CPU debugger + asset tracer, built for translators and romhackers taking a game apart.

Inputs it reads

Live emulator · Yabause / Mednafen savestates · raw memory dumps · disc images (.iso/.bin/.cue)

Runs on

Windows (D3D11) · Linux / macOS (SDL2) · Web (browser, no install)

Graphics inspection

See what the console is drawing

Saturn Explorer is a software VDP1 + VDP2 — it rebuilds the frame from individual sprite quads and background layers rather than reading back the emulator's framebuffer, so every pixel is traceable to the command that drew it.

Composited frame

VDP Output

The reconstructed 4:3 frame, software-composited from the VDP1 sprites and VDP2 background layers. Click a pixel to select the command that drew it; overlay bounding boxes and object numbers.

Exploded scene

3D View

An orbit-camera view with every sprite exploded along Z by priority. Drag to orbit, wheel to zoom, click to pick a command — useful for untangling layered scenes.

Draw commands

VDP1 Command List

Every parsed draw command — type, size, position, color mode, texture address. Size and position are inline-editable and write straight back to VDP1 VRAM.

Field inspector

Selected Object

Every field of the command under the cursor — table / link / texture addresses, size, position, color and draw mode, flip, and the raw CMDCTRL / CMDPMOD words.

Texture

Texture Viewer

Decodes the selected sprite's texture over a checkerboard. Export to BMP (keeping the game's palette), break on any write to it, or search the game files for it.

Palette

Palette Viewer

The sprite's CLUT / CRAM colors as swatches; hover any entry for its index and raw RGB value.

VRAM at a glance

VRAM Map

A color-coded map of all 512 KiB of VDP1 VRAM — textures, CLUTs, the command table, gouraud tables, free space — with a percent-used readout. Click to select the nearest command.

Layer toggles

Show / hide layers

Flip individual VDP1 overlays (sprites, wireframe, boxes, object numbers) and VDP2 layers — NBG0–3, RBG0, windows, color calculation, and shadow / highlight — to isolate what you're studying.

Memory & data

Read and edit every region

All of the console's captured memory — work RAM, sound RAM, VDP1/VDP2 VRAM, Color RAM, the framebuffer, and hardware registers — is browsable and editable. On a live emulator, edits are poked into the running game.

Hex editor

Memory

A region-tabbed hex editor over every captured region. Type-to-edit — select a byte and just start typing hex. ASCII or Shift-JIS text pane, change highlighting, and GoTo from any other panel.

Live write-back

Edits reach the game

A write updates the snapshot and — when connected live — pokes the emulator, so the change persists in the running game. On a savestate the edit stays in the in-memory image.

Raw tables

VDP1 & VDP2 Tables

The raw 15-word VDP1 command table per command, and the decoded VDP2 background config — each NBG's on/off, color depth, priority, and scroll.

Palette memory

Color RAM & Registers

The full CRAM as a swatch grid (RGB555 / RGB888), plus tabbed VDP1 / VDP2 hardware register tables with name, address, and value.

Cross-reference

References

Every other sprite that shares the selected texture or palette — click to jump between them.

Snapshot

Dump Memory

Save every region plus the registers into one self-describing .sedump file for offline analysis or sharing.

Live debugging

Step the code, watch it run

Connected to a running, patched emulator, every panel tracks the live game — the disassembly follows the program counter, breakpoints and tracepoints fire, and you can drive execution frame-by-frame or instruction-by-instruction.

Disassembly

SH-2 Assembly

Live disassembly of the master and slave SH-2, following the PC. Gutter breakpoints, run-to-cursor, step into / over / out, your own labels and comments, add-operand-to-watch, and create-tracepoint.

Halt on…

Breakpoints

Execution and data (read / write / read-or-write) breakpoints, each shown as a plain-English "breaks when…" sentence, with an optional guard expression over registers and memory.

Track values

Watch

Track addresses and expressions, refreshed continuously with change tinting. Typed as U8…S32, RGB555 (with a swatch), or Pointer. Break on change straight from a row.

Non-halting logging

Tracepoints

Attach a format string like "Dialogue ID = {r4}" to an instruction; every time it runs, the value is captured to the Log — without pausing the game. Autocomplete for register and memory tokens; hit counts.

Backtrace

Call Stack

The per-CPU call chain with confidence levels — it reconstructs a plausible stack even on a static savestate with no emulator. Rename functions and load a symbol map.

Cheat-Engine style

RAM Search

Scan work RAM for a value, then narrow: equal / greater / less, or increased / decreased / unchanged / changed between scans. Send any hit to the hex editor or watch list.

Who touched this?

Access Log

"Find what accesses this address": a non-halting watchpoint records every instruction that reads or writes it, with hit counts and each accessor's call stack.

Event feed

Log & Symbols

A filterable, searchable event log — click an entry to jump to the instruction or address that produced it. An address→name store imports .map / .sym symbol files.

Audio

Trace a sound to its sample

The SCSP sound chip's 32 voices, the 68000 sound driver, and the raw PCM behind each voice — inspect them, play them back, and export them.

32 voices

Sound (SCSP)

One row per voice: envelope phase and level, sample format, pitch in Hz, total level, pan, loop mode, and start / loop addresses. A start-address cell jumps to that sample in Sound RAM. Play a voice, or export it to WAV.

68000

Sound CPU (68K)

Disassembles the SCSP sound driver from Sound RAM from any address, with clickable branch targets to follow the code.

Files, disc & input

Back to the disc — and drive the game

Browse the game's filesystem, resolve what the drive is streaming right now, search the files for an asset's bytes, and control the emulated console with an on-screen pad.

ISO 9660

Disc Explorer

Open an .iso / .bin / .cue and browse the filesystem. Resolve any sector or FAD to a file + offset, and — with the CD tap — see which file the drive is reading right now.

Asset tracing

Find in game files

Search the extracted game files for a texture's or palette's raw bytes — exact or PRS-compressed — to find where the asset lives on disc.

Virtual pad

Controller

An on-screen Saturn pad that drives the live game directly, with key bindings, input recording, macros, and a timeline — handy for reaching a repeatable state.

Recording & rewind

Scrub backward through time

Saturn Explorer keeps a rolling, compressed buffer of recent frames. Pause and drag the transport back, and every panel re-renders that past moment — then, on a rewind-capable emulator, resume from there with your edits applied.

Rolling buffer

Frame recording

Recent frames are LZ-compressed into an in-memory ring bounded by a length and a memory ceiling; the status bar shows used / available. Configure the maximum length in Recording Settings.

Time travel

Scrub the transport

Pause and drag the slider under VDP Output to step back through recorded frames. Every panel — graphics, memory, sound — reflects the frame you land on.

Re-simulate

Play from here

On a rewind-capable emulator, pressing Play from a past frame restores its full savestate, applies any edits you made while scrubbed, and re-simulates forward — a true rewind, not just a replay.

Patching

From a memory edit to a patched disc

Saturn Explorer learns where a memory value lives in the game's files by content search, remembers those locations in a project, and writes your changes back into the files.

Locate

Find in game files

From a hex selection, search the extracted files — widen the match with adjustable surrounding-byte context until it's unique — and accept a result into the location library.

Write it out

Apply changes to disc

Generates and runs a self-contained Python script that writes only your changed bytes into their mapped files, then reports what changed, what didn't, and what couldn't be read.

Persist

Projects

Save the whole library of known locations to a .seproj project and reopen it later. Unsaved changes prompt a Save / Discard warning when you close the app.

Inputs & platforms

One codebase, three ways to run

Windows

Win32 + Direct3D 11

The primary target. Full feature set including live mode. A one-command installer also builds a patched emulator for you.

Linux / macOS

SDL2 + OpenGL

The same features as Windows, live mode included. Build patched Mednafen or Yabause from source, then launch with --live.

Web

SDL2 + WebGL2 · Emscripten

Savestate and dump analysis in a browser, no install. Live mode is desktop-only (it needs sockets and threads a browser can't provide).

Savestates & dumps

  • Yabause family — .yss (Yabause, Yaba Sanshiro, Kronos)
  • Mednafen / Beetle Saturn savestates
  • Raw memory dump, or a labeled region-file directory

Live & disc

  • Live emulator — a patched Yabause or Mednafen over a local socket
  • Disc images — .iso, .bin / .img (2352-byte), with .cue
  • Symbols — import a .map / .sym address→name file
